# ТЗ: интернет-магазин Telegram-ботов «BotForge» (MVP)

Версия 4 · @Matvey

## 1. Общие сведения

BotForge — сайт-каталог готовых Telegram-ботов, модулей и услуг. Клиент собирает корзину и оставляет заявку, менеджер связывается с ним и доводит сделку вручную. Онлайн-оплаты нет: ботов на заказ всё равно продают через созвон и согласование, а не в один клик.

Сайт — рабочая витрина студии: ссылку на него отправляют потенциальным клиентам, а все заявки собираются в одной админке и дублируются в Telegram.

### 1.1. Роли

| Роль | Как попадает | Что может |
|---|---|---|
| Гость | Открывает сайт | Смотрит каталог, пробует демо-ботов, собирает корзину (localStorage), оставляет заявку |
| Администратор | Вручную заходит по секретному адресу админки (`ADMIN_PATH`) | CRUD товаров и категорий, работа с заявками, редактирование «О магазине», подключение Telegram-уведомлений |

Аккаунтов покупателей нет: клиент студии покупает один раз, личный кабинет и серверная корзина ему не нужны (см. раздел 8).

### 1.2. Стек

| Слой | Технология |
|---|---|
| Frontend | Vue 3 + TypeScript + Vite, Vue Router, Pinia, Tailwind CSS |
| Backend | Node.js + TypeScript, Fastify (или Express) |
| БД | PostgreSQL + Prisma |
| Telegram | grammY, работает в том же процессе, что и API |
| Деплой | VPS + Docker Compose (web, api, postgres) + Nginx + Let's Encrypt |

REST API с префиксом `/api/v1`. Ошибки в едином формате `{ code, message, fields? }`.

### 1.3. Границы MVP

- **Входит:** главная с каталогом, карточка товара, «О магазине», виджет корзины, оформление заявки, уведомление в админку и в Telegram, вход администратора, админ-панель.
- **Не входит:** аккаунты покупателей, онлайн-оплата, AI-функции на сайте, отзывы, мультиязычность. Всё это перечислено в разделе 8 как бэклог.

## 3. Публичная часть

### 3.1. Страницы

| Маршрут | Страница |
|---|---|
| `/` | Главная: витрина и информация |
| `/product/:slug` | Карточка товара |
| `/about` | О магазине |
| `/checkout` | Оформление заявки (только при непустой корзине) |
| `/order/success` | Заявка принята |
| `ADMIN_PATH` (например `/cp-7f3k9q`) | Вход и админ-панель, отдельное приложение (см. 5.1) |
| `*` | 404 с кнопкой «В каталог» |

### 3.2. Главная

1. Шапка: логотип, «Каталог», «О магазине», иконка корзины со счётчиком. Кнопки входа нет.
2. Hero-блок: заголовок, подзаголовок, кнопка «Смотреть ботов». Тексты редактируются в админке.
3. «Популярное»: до 4 товаров с `isFeatured`.
4. Каталог: фильтр по категориям (чипсы), сортировка (по умолчанию / цена ↑ / цена ↓), поиск по названию с debounce 300 мс. Сетка: 1 колонка на мобильном, 2 на планшете, 3–4 на десктопе. Подгрузка по 12 товаров кнопкой «Показать ещё».
5. Карточка в сетке: картинка, название, краткое описание (2 строки), цена, кнопка «В корзину». Если товар уже в корзине, кнопка превращается в счётчик «− n +».
6. «Как это работает»: выбрали → оставили заявку → менеджер связался.
7. Подвал: контакты и Telegram из настроек магазина.

Состояния: скелетоны во время загрузки, сообщение и «Повторить» при ошибке, «Ничего не найдено» при пустом поиске.

### 3.3. Карточка товара

- Галерея: основная картинка и превью.
- Название, категория, цена, полное описание (Markdown → HTML через DOMPurify), список возможностей с галочками.
- **Кнопка «Попробовать демо»**, если заполнен `demoUrl`, и видео, если заполнен `videoUrl`.
- Количество и кнопка «В корзину». Для товаров с типом `FROM_HOURLY` количества нет, всегда 1, цена показывается как «от 1 500 ₽/час».
- «С этим покупают»: до 3 товаров из категорий «Модули» и «Услуги».
- Товар не опубликован или удалён → 404.
- `<title>` и meta description берутся из товара.

### 3.4. О магазине

Заголовок, текст в Markdown, контакты (телефон, email, Telegram), режим работы, до 4 картинок. Всё редактируется в админке. Пока не заполнено, показывается заглушка.

### 3.5. Виджет корзины

Выезжающая справа панель, на мобильном во весь экран. Отдельной страницы корзины нет.

- **Открытие:** клик по иконке в шапке. После добавления товара показывается toast «Добавлено» с кнопкой «Открыть».
- **Закрытие:** крестик, клик по фону, Esc.
- **Содержимое:** позиции (мини-картинка, название, цена, счётчик «− n +», сумма строки, удаление), итог, кнопки «Оформить заявку» и «Очистить» (с подтверждением).
- **Итог с почасовыми услугами:** «Итого от 12 800 ₽ + почасовые работы по оценке».
- **Пустая корзина:** текст и кнопка «В каталог».
- **Хранение:** Pinia + localStorage (ключ `cart:v1`), хранятся только `productId` и `quantity`.
- **Актуализация:** при открытии виджета вызывается `POST /api/v1/cart/preview`. Снятый с публикации товар помечается «Недоступен» и не попадает в заявку, изменившаяся цена показывается с пометкой.
- **Ограничения:** количество 1–99, не больше 50 позиций.

## 4. Заявка и уведомления

Заявка сначала сохраняется в БД, потом отправляется уведомление. Если Telegram недоступен, заявка не теряется: она уже есть в админке, а сообщение дойдёт позже.

### 4.1. Форма `/checkout`

Слева состав корзины (только чтение, ссылка «Изменить» открывает виджет), справа форма.

| Поле | Обязательно | Валидация |
|---|---|---|
| Имя | Да | 2–60 символов |
| Телефон | Да | Маска +7 (XXX) XXX-XX-XX |
| Telegram | Нет | `^@?[A-Za-z0-9_]{5,32}$` |
| Способ связи | Да | Телефон / Telegram |
| Комментарий | Нет | До 1000 символов, подсказка «Опишите ваш бизнес и задачу» |
| Согласие на обработку ПД | Да | Без него кнопка неактивна |

### 4.2. Сервер `POST /api/v1/orders`

1. Валидация (zod-схема, общая для фронта и бэка).
2. Антиспам: скрытое поле-ловушка (honeypot), лимит 5 заявок в час с IP, заголовок `Idempotency-Key` против двойного клика.
3. Цены берутся из БД, цены от клиента игнорируются. Неопубликованные товары отбрасываются, если позиций не осталось — ошибка 422.
4. В одной транзакции создаются `Order` (статус `NEW`, номер `BF-000123`), `OrderItem` со **снимком названия и цены** и запись в `NotificationOutbox`.
5. Ответ `201` с номером. Фронт очищает корзину и переходит на `/order/success`, передавая номер через state роутера. Страница успеха **не запрашивает** данные заявки с сервера, поэтому перебором номеров ничего не узнать.

### 4.3. Уведомление в админке

Бейдж с числом заявок `NEW` у пункта «Заявки». Админка раз в 30 секунд запрашивает `GET /api/v1/admin/orders/unread-count`. При росте счётчика показывается toast, а в заголовке вкладки появляется «(2) Админка».

### 4.4. Telegram-бот

**Привязка.** В «Настройках» кнопка «Подключить Telegram» создаёт одноразовый токен (10 минут) и ссылку `t.me/<bot>?start=<token>`. Бот сохраняет `chat_id` получателя. Можно подключить несколько человек или групповой чат.

**Сообщение:**

```
🛒 Новая заявка BF-000123
Имя: Иван · +7 978 123-45-67 · @ivan
Связаться: Telegram

• Бот записи к специалисту × 1 — 9 900 ₽
• Настройка и деплой на VPS × 1 — 2 900 ₽
Итого: 12 800 ₽

Комментарий: барбершоп, нужно до конца месяца
```

Кнопки: «Взять в работу» (статус `IN_PROGRESS`, сообщение дополняется строкой «В работе: @admin») и «Открыть в админке».

**Отправка.** Раз в 10 секунд процесс берёт записи outbox со статусом `PENDING`, отправляет их и ставит `SENT`. При ошибке увеличивает `attempts`, после 5 неудач ставит `FAILED`, и в карточке заявки появляется отметка «Уведомление не доставлено». Если получатель заблокировал бота (ошибка 403), он деактивируется.

## 5. Авторизация администратора

- **Создание:** регистрации нет. Админ создаётся командой на сервере `npm run admin:create`, пароль вводится интерактивно.
- **Пароль:** минимум 10 символов, хеш argon2id. Пароль нигде не хранится и не логируется.
- **Сессия:** после входа в БД создаётся запись `Session` (хеш токена, срок 7 дней), браузер получает cookie `sid` с флагами `HttpOnly; Secure; SameSite=Lax`. JWT в localStorage не используется: его крадёт любой XSS, а сессию в БД можно отозвать.
- **CSRF:** `SameSite=Lax` и проверка заголовка `Origin` на изменяющих запросах.
- **Доступ:** guard на фронте только прячет интерфейс. Каждый `/api/v1/admin/*` проверяется на сервере: нет сессии → 401.
- **Адрес админки:** не `/admin`, а неочевидный путь из переменной окружения `ADMIN_PATH` (см. 5.1).

### 5.1. Адрес админки

Неочевидный путь не заменяет защиту, но отсекает ботов-сканеров, которые круглосуточно перебирают `/admin`, `/wp-admin`, `/login` и т. п. Меньше мусора в логах и меньше попыток подбора пароля.

- Путь задаётся в `.env` переменной `ADMIN_PATH` (например `/cp-7f3k9q`) и меняется без правки кода.
- **Админка собирается как отдельное приложение** (вторая точка входа Vite, `admin.html`). Если сделать её просто роутом внутри витрины, путь окажется в JS-бандле, который скачивает любой посетитель, и «секретный» адрес находится поиском по файлу за минуту.
- Nginx отдаёт `admin.html` только по `ADMIN_PATH`. Запросы на `/admin` получают обычную страницу 404, без намёка, что админка существует.
- Страница входа: `noindex`, путь не упоминается в `robots.txt` (иначе это прямая подсказка), нет ссылок с сайта.
- API админки (`/api/v1/admin/*`) остаётся на обычном пути: он защищён сессией и лимитами, и без входа отвечает только 401.
- Если адрес утёк, достаточно поменять `ADMIN_PATH` и перезапустить контейнер.

| Ситуация | Что происходит |
|---|---|
| Подбор пароля | 5 неудачных попыток за 15 минут с одного IP → блокировка входа на 15 минут, сообщение админу в Telegram |
| Вход с нового IP | Бот присылает «Вход в админку: IP, браузер, время» |
| Забыл пароль | `npm run admin:reset-password` на сервере. Удалённого сброса нет намеренно |
| Сессия истекла во время работы | API отвечает 401, фронт перекидывает на вход и после него возвращает на ту же страницу |
| Выход | Сессия удаляется из БД, cookie очищается |

## 6. Админ-панель

Отдельное Vue-приложение (`admin.html`), открывается по `ADMIN_PATH`, код админки не попадает в бандл витрины. Меню: Заявки, Товары, Категории, О магазине, Настройки.

### 6.1. Товары

- **Список:** превью, название, категория, цена, статус (опубликован / черновик), «Популярное». Поиск, фильтр по категории и статусу, пагинация по 20.
- **Создание и редактирование** (одна форма):

| Поле | Правила |
|---|---|
| Название | 3–120 символов |
| Slug | Генерируется транслитом из названия, можно править, уникален, `a-z0-9-` |
| Категория | Обязательно |
| Цена и тип цены | Целое ≥ 0, `FIXED` или `FROM_HOURLY` |
| Краткое описание | До 200 символов |
| Полное описание | Markdown с предпросмотром |
| Возможности | Список строк |
| Картинки | До 6, первая — обложка |
| Ссылка на демо, ссылка на видео | Необязательно, валидный URL |
| Опубликован, Популярное | Переключатели |

  При уходе со страницы с несохранёнными изменениями — подтверждение. Ошибки 422 подсвечиваются у полей.
- **Картинки:** `POST /api/v1/admin/uploads`, только JPEG, PNG и WebP (проверка по сигнатуре файла), до 5 МБ, пересжатие через sharp в WebP, случайное имя файла.
- **Удаление:** мягкое (`deletedAt`). Товар пропадает с сайта, но остаётся в старых заявках благодаря снимку. Перед удалением — модалка с названием товара.

### 6.2. Категории

Создать, переименовать, задать порядок. Удалить можно только пустую категорию, иначе 409.

### 6.3. Заявки

- Список: номер, дата, имя, контакт, сумма, статус. Новые выделены. Фильтр по статусу, поиск по номеру, имени и телефону.
- Статусы: `NEW` → `IN_PROGRESS` → `COMPLETED` или `CANCELLED`.
- Карточка: контакты (телефон кликабелен, Telegram открывается ссылкой), состав со снимком цен, комментарий клиента, внутренняя заметка менеджера, отметка о доставке уведомления.

### 6.4. О магазине

Одна запись `StoreSettings`: название, тексты hero-блока, страница «О магазине» (заголовок, Markdown, картинки), контакты, режим работы, meta title и description главной.

### 6.5. Настройки

Подключение Telegram, список получателей, кнопка «Отправить тестовое уведомление», смена своего пароля.

### 7.3. Нефункциональные требования

- Адаптив от 360 до 1920 px, актуальные Chrome, Firefox, Safari, Edge.
- HTTPS, helmet, санитизация Markdown, секреты только в `.env` (не в git).
- Политика конфиденциальности на отдельной странице, чекбокс согласия в форме, данные хранятся на сервере в РФ.
- Виджет корзины и модалки управляются с клавиатуры, есть `aria`-атрибуты.
- Ежедневный `pg_dump` с хранением 7 дней, healthcheck `/api/health`.
- ESLint + Prettier, TypeScript strict, unit-тесты на создание заявки (снимок цен, отбрасывание неопубликованных товаров) и на вход (блокировка после 5 попыток).
- Репозиторий содержит `.env.example` с пустыми значениями, реальные токены и пароли в git не попадают.

### 7.4. Этапы

1. **Основа:** репозиторий, Docker Compose, Prisma-схема, сид каталога.
2. **Витрина:** главная, карточка, «О магазине», виджет корзины.
3. **Заявки:** форма, создание заявки, страница успеха.
4. **Админка:** вход, CRUD товаров и категорий, картинки, заявки, «О магазине».
5. **Деплой:** VPS, домен, HTTPS, бэкапы.
6. **Telegram:** привязка, outbox, кнопка «Взять в работу», оповещение о входе.
7. **Финал:** README с инструкцией запуска, проверка по критериям приёмки.

### 7.5. Критерии приёмки

- [ ] Гость находит товар через фильтр или поиск, открывает карточку, переходит в демо-бота и добавляет товар в корзину
- [ ] Корзина открывается виджетом, пересчитывает сумму и переживает перезагрузку страницы
- [ ] Почасовая услуга добавляется без выбора количества, итог показывается как «от …»
- [ ] Заявка получает номер и появляется в админке в статусе `NEW` в течение 30 секунд
- [ ] Админ получает сообщение в Telegram и берёт заявку в работу кнопкой
- [ ] При выключенном боте заявка создаётся, а уведомление доходит после его запуска
- [ ] Любой запрос к `/api/v1/admin/*` без входа возвращает 401
- [ ] `/admin` отдаёт 404, админка открывается только по `ADMIN_PATH`, в JS-бандле витрины этого пути нет
- [ ] Админ создаёт, редактирует, снимает с публикации и удаляет товар, изменения сразу видны на сайте
- [ ] Изменение цены не меняет суммы уже созданных заявок
- [ ] Изменения «О магазине» видны на сайте после сохранения
- [ ] Шестая неудачная попытка входа за 15 минут блокируется
- [ ] В README есть инструкция запуска (`docker compose up`, сиды, создание админа)

## 8. Бэклог (после сдачи и запуска)

В порядке пользы для бизнеса:

1. **AI-черновик ответа клиенту в админке:** по заявке модель пишет ответ с уточняющими вопросами и вилкой по цене. Ключ API только на сервере. С сервера в РФ доступны YandexGPT и GigaChat, API OpenAI и Anthropic официально недоступны.
2. **AI-помощник подбора на витрине:** клиент описывает бизнес, модель советует товары только из каталога. Нужны лимиты запросов и защита от абьюза публичной формы.
3. **Кейсы / портфолио:** раздел с реальными проектами и скринами.
4. **Метрики:** Яндекс.Метрика, цели «добавил в корзину» и «отправил заявку», UTM-метки в заявке.
5. **Онлайн-оплата предоплаты** через ЮKassa (вебхуки, чеки по 54-ФЗ).
6. **2FA для админа** через подтверждение в боте, журнал действий (AuditLog).
7. **Аккаунты покупателей,** личный кабинет и серверная корзина — только если появятся повторные покупатели (например, клиенты на абонентке).
8. **Перенос витрины в Telegram Mini App.**
